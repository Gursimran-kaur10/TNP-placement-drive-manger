# Placement Drive Manager

A small full-stack app for the Training and Placement Cell. It uses Next.js, JavaScript, Tailwind CSS, PostgreSQL and Prisma.

What the app does

- Adds a placement drive with company name, role, date, eligible branches, minimum CGPA, and job type.
- Checks the submitted data on the server before saving it.
- Saves records in PostgreSQL so they remain available after a page refresh or server restart.
- Loads all saved drives and sorts them by drive date.
- Filters the list by company name, role, or eligible branch.
- Shows loading, success, empty, and error messages in the interface.

## Technology choices

| Technology | What it does here |
| --- | --- |
| Next.js App Router | Serves the page and the API route from one project. |
| JavaScript and React | Build the interface and handle form state and API requests. |
| Tailwind CSS | Style the responsive interface with utility classes. |
| PostgreSQL | Persist placement drive records in a relational database. |
| Prisma ORM | Define the data model and read/write records without hand-writing query code in the route. |
| Vercel | Can host the Next.js app; a hosted PostgreSQL provider supplies the database. |

## Run locally

1. Install packages:

   ```bash
   npm install
   ```

2. Copy `.env.example` to `.env` and add your PostgreSQL connection string as `DATABASE_URL`.

3. Apply the migration already included in this project:

   ```bash
   npm run db:migrate
   ```

   When you later change `prisma/schema.prisma`, create a named migration with `npm run db:migrate -- --name describe_the_change`.

4. Start the app:

   ```bash
   npm run dev
   ```

Open [http://localhost:3000](http://localhost:3000).

How the app works

### When someone opens the page

1. `app/page.js` renders the `DriveManager` component.
2. `components/DriveManager.js` makes a `GET /api/drives` request when the page loads.
3. The API route asks Prisma for records in date order.
4. The page displays the records, or an empty/loading/error state.

### When someone submits the form

1. The browser checks required inputs and sends a JSON `POST /api/drives` request.
2. The API parses the JSON and calls `validateDrive` from `lib/drive-validation.js`.
3. Invalid data receives a `400 Bad Request` response with a useful message.
4. Valid data is saved by Prisma to PostgreSQL.
5. The API returns `201 Created`; the interface clears the form and reloads the list.

## Database model

The model is in `prisma/schema.prisma`:

```prisma
model PlacementDrive {
  id             String   @id @default(cuid())
  companyName    String
  role           String
  driveDate      DateTime
  eligibleBranch String
  minCGPA        Float?
  jobType        String?
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt

  @@index([driveDate])
  @@index([companyName])
}
```

- `id` is a unique ID generated by Prisma.
- `companyName`, `role`, `driveDate`, and `eligibleBranch` are required.
- `minCGPA` and `jobType` are optional; the `?` means the database field can be empty.
- `createdAt` is set when the record is created. `updatedAt` is refreshed on updates.
- Indexes on date and company name help common lookup and sorting operations.

The database connection is read from `DATABASE_URL`; credentials are not written into source code.

## API

### `GET /api/drives`

Returns all placement drives ordered by drive date (earliest first).

Example response (`200 OK`):

```json
[
  {
    "id": "cm123example",
    "companyName": "Acme Technologies",
    "role": "Graduate Engineer Trainee",
    "driveDate": "2026-11-10T00:00:00.000Z",
    "eligibleBranch": "CSE, IT",
    "minCGPA": 7,
    "jobType": "Full-Time",
    "createdAt": "2026-10-20T10:30:00.000Z",
    "updatedAt": "2026-10-20T10:30:00.000Z"
  }
]
```

### `POST /api/drives`

Creates a placement drive. Required fields: `companyName`, `role`, `driveDate` (ISO date), and `eligibleBranch`. `minCGPA` must be between 0 and 10. `jobType` can be `Internship`, `Full-Time`, or `Other`.

Example request:

```json
{
  "companyName": "Acme Technologies",
  "role": "Graduate Engineer Trainee",
  "driveDate": "2026-11-10",
  "eligibleBranch": "CSE, IT",
  "minCGPA": 7,
  "jobType": "Full-Time"
}
```

Returns `201 Created` with the saved record, `400 Bad Request` for invalid input, or `500 Server Error` if the database request fails.

## Deploy to Vercel

1. Push this folder to a GitHub repository and import it in Vercel.
2. Add `DATABASE_URL` in the Vercel project environment variables. A hosted PostgreSQL provider such as Neon or Supabase can provide the connection string.
3. Before the first deployment, run `npm run db:deploy` from a machine with the production database URL set. This applies the committed Prisma migrations.
4. Deploy. Vercel installs dependencies, generates Prisma Client and builds the Next.js app.
